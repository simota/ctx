# SQI 品質評価 — 2026-11（設計・アーキテクチャ・ビジュアル・UX）

SQI（Software Quality Improvement Index）は本リポジトリ用の独自ルーブリックです。
物理量ではなく、下記の固定基準に基づく**評価値**です。実ユーザーテストは実施していません
（UX のタスク評価は AI による操作であり、ユーザーテストの代替ではありません）。

- 対象: `e782f34`（改善前）と本ブランチ（改善後）
- 重み: DQI / AQI / VQI / UXQI 各 0.25（調査時点で確定、前後で不変）
- 領域スコア = Σ(項目の重み × 評点 ÷ 5)。評点は 0〜5（下記判定基準）
- エビデンス: E1 = コード・画面の観察 / E2 = 再現可能な静的解析・自動テスト・体系的検証 / E3 = 実測・複数根拠

## 2. 判定基準（各項目 0〜5）

共通: 0 致命的 / 1 重大欠陥が複数 / 2 繰り返し問題 / 3 実用上おおむね問題なし / 4 一貫して高品質 / 5 例外ケースまで根拠付きで高品質。
以下は項目ごとの具体基準（改善作業前に確定）。

### DQI

| 項目 | 重み | 判定基準 |
|---|---:|---|
| 責務分離 | 20 | 5: 3つ以上の変更理由が混在するモジュールなし / 4: そのようなホットスポット ≤2 / 3: 3〜5 / 2: 6以上 |
| 凝集度 | 15 | 5: 全モジュールが単一目的 / 4: 単一目的が大半、例外はホットスポットのみ / 3: 無関係なユーティリティの混在が散見 |
| インターフェース・契約 | 15 | (a) 型による契約（4: strict TS・Rust 型・JSON schema、5: 加えて実行時検証）と (b) CLI オプション文書化率 ×5 の平均 |
| 変更容易性 | 15 | 代表変更（ファイル種別追加・CLI フラグ追加・テーマ追加・API 追加）の影響ファイル数。4: 全シナリオ ≤3 ファイルで手順が明示 |
| 可読性 | 10 | 4: 命名一貫・設計意図コメントあり、読解困難な巨大単位が ≤2 |
| テスト容易性 | 15 | 5: 全層がオフライン実行可能な自動テストを持ち外部依存なし / 3: 全層にハーネスあり、一部ロジックが試験困難な単位に残る / 2: 自動テストハーネスがない層がある |
| 不変条件・例外処理 | 10 | 4: 本番コードの unwrap/握りつぶしほぼゼロ、境界値に上限・検証あり |
