ctx (LLM Context Curator) は、AI コーディングツール (Claude Code / Cursor) に渡すソースファイルを、ゴールに照らして選り分け、省いたものも記録する Rust CLI / TUI / MCP server です。トークン予算管理・goal-aware スコアリング・Secret 検出・監査ログを内蔵。通常ビルドは Rust toolchain のみ、外部送信ゼロ。

The problem

届いていない AI への問いかけ。

コンテキストウィンドウは、気づいたら溢れている

ファイルを貼るたびに「何トークン使ったか」がわからない。 気づいたらウィンドウが埋まり、古いコンテキストが押し出される。 LLM の「注意」がどこに向いているか把握できない状態で会話が続く。

全部貼る、は問題を先送りにしているだけだ

関係しそうなファイルを片端から貼る。lock ファイル、生成物、 巨大 JSON も一緒に流れ込む。LLM は大量の低品質コンテキストに 引きずられ、回答精度が下がる。省く判断を後回しにした代償は大きい。

「先週 AI に何を渡したか」が残らない

「あのとき LLM に何を渡したか」が残らない。 デバッグの文脈を再構築するたびにゼロからやり直し。 チームメンバーに共有しようとしても、状態が揃わない。

何を省いたかが残る道具が、なかった。

The solution

ctx は、LLM Context Curation のための道具だ。

ctx はコードベースを一覧し、自然語のゴールから要るファイルを選り分け、 入らなかったものを Skipped 理由付きで残します。 LLM に手渡す前に、curator の手つきを 1 段挟むための道具です。

How it works

3 ステップで選り分ける。

Step 01 — 俯瞰する

リポジトリを一覧する

--tokens --git --symbols を付けると、 ファイル横にトークン数・Git 状態・シンボル名が並ぶ。 「どこが重くて、何が変わっているか」がひと目でわかる。 

$ ctx --tokens --git --symbols .

crates/ctx-cli/src/main.rs   git:M  tokens:812   symbols:main
crates/ctx-pack/src/lib.rs          tokens:4.9k  symbols:pack,score

Step 02 — 見切る

トークン予算内で何が入るか見る

--budget 50000 でコンテキストウィンドウに 収まるファイルを自動選定。 進捗バーで残量をリアルタイム把握。 収まらなかったものは理由付きで Skipped に回る。 

$ ctx --budget 50000 .

Context Budget: 50,000 tokens
[████████████████░░░░] 35,420 / 50,000

Included (24 files)
└─ crates/ctx-pack/**   8,400 tokens

Step 03 — 手渡す

--explain で、省いた理由まで見せる

自然語のゴールを与えると、basename / path / symbol / content の 4 シグナルでスコアリングし、関連度の高いファイルだけを選り分ける。 --explain で「なぜ含め、なぜ省いたか」が残る。 

$ ctx pack \
    --goal "ログイン認証のバグを調べたい" \
    --budget 30000 \
    --explain \
    --out context.md .

High   crates/ctx-cli/src/main.rs   score 28
Medium crates/ctx-pack/src/lib.rs   score 14
Skipped node_modules/  outside goal scope

Features

省く判断を、道具が支える。

最初に試すならここから

w ctx where — ゴール起点の選定

basename / path / symbol / content の 4 シグナル合成スコアで 関連ファイルをランキング。ゼロヒット時は Levenshtein 距離で typo 候補を提示。--all で AND セマンティクス、 --regex で Rust regex フィルタ、--literal で正規化なしの exact パターンも組み合わせ可能。 

ctx where "ログイン処理"
ctx where "AuthMiddleware" --format json
ctx where "ABテスト" --literal "ABテスト"

p ctx pack — 選り分けてパック

自然語ゴールに対して High / Medium / Skipped に振り分け。 --diff で PR 差分のみ、--changed で 作業中の変更のみを対象に。--watch で ファイル保存ごとに自動再生成。 

ctx pack --goal "認証バグ" --budget 30000
ctx pack --diff main..HEAD --api-only
ctx pack --watch --out ~/.context.md

m MCP server — 毎朝の儀式を 1 行に

ctx mcp serve で JSON-RPC 2.0 stdio server が立ち上がる。 ctx_pack / ctx_where / ctx_budget / ctx_symbols / ctx_skim / ctx_digest / ctx_focus / ctx_tree の 8 tool を Claude Code / Cursor から tool call で呼び出せる。 

{
  "mcpServers": {
    "ctx": {
      "command": "ctx",
      "args": ["mcp", "serve"]
    }
  }
}

r ctx replay — 選定を読み返す

--snapshot ID でその時点のパック選定を manifest として保存。 翌日 --since-snapshot ID を使えば差分のみを pack。 ctx replay diff で「AI に渡した文脈の進化」を可視化できる。 

ctx pack --snapshot baseline --budget 30000
# 翌日: 差分のみ渡す
ctx pack --since-snapshot baseline

まずは 1 ファイル省くところから

Rust toolchain でビルドでき、外部送信ゼロ。ctx pack --explain で省いた理由まで記録できます。

Enterprise & Teams

金融・医療・インフラ現場でも、省ける安心を。

ctx はすべてローカルファースト。AI 呼び出しは将来も opt-in のみ。 --strict-offline で外部通信を完全に遮断できる。

ctx.toml — 設定例

[security]
strict_offline  = true
secret_scan     = true
enable_entropy  = false
allowlist_files = ["tests/fixtures/**"]

[hooks]
pre_pack  = "./scripts/dlp-scan.sh"
on_secret = "./scripts/security-alert.sh"

[audit]
enabled          = true
path             = "/var/log/ctx-audit.jsonl"
query_handling   = "mask"

[where.synonyms]
session = ["cookie", "jwt", "oauth"]
auth    = ["authentication", "login"]

監査ログ — 操作の全量を選り分け、記録する

すべての操作が JSONL 形式で記録される。各行に前行の SHA-256 を prev_hash として埋め込む hash chain 方式で改ざん検知が可能。 ctx audit verify で整合性を一発確認。 query_handling = "mask" で検索クエリも正規表現でマスクできる。

Secret 検出 — 渡す前に、漏れを見切る

AWS / GCP / Azure / GitHub / Slack / JWT / 秘密鍵などのパターンを pack 前に自動スキャン。検出時は on_secret hook が発火し、 pack を中断してアラートを送れる。allowlist_files で false positive を抑制。

Strict offline — 外部に手渡さない保証

strict_offline = true または環境変数 CTX_STRICT_OFFLINE=1 で完全オフライン動作。 ctx doctor がすべてのコンポーネントの ローカル性を証跡として提示する。

Use cases

何を省くかで、仕事の質が変わる。

PR レビュー

差分だけを、API シグネチャだけを渡す

--diff main..HEAD --api-only で、main からの差分について 公開 API の Before/After のみを side-by-side で生成。 実装詳細は省かれ、レビューに集中できる。 

ctx pack --diff main..HEAD \
  --api-only --out review.mdx

バグ調査

ゴールに関連するファイルだけを AI に渡す

goal 関連度で基幹ファイルを High に、関連 helper を Medium に、 無関係ファイルは outside goal scope として省く。 --explain で「なぜ含めたか」が見えるので AI への信頼度が上がる。 

ctx pack \
  --goal "セッションが消える" \
  --budget 40000 --explain

OSS オンボーディング

最初に読むべきファイルを選り分ける

entry/role、git churn、symbol density、basename references の 合算スコアで読む順序を決定。--persona ai で 新参 LLM session 用の圧縮形式に切り替え可能。 初日に「どこから読めばいいか」で迷わない。 

ctx onboarding --persona ai
ctx onboarding --limit 20

週次 Digest

この 1 週間で何が変わったかを 1 ページに

ctx digest は git churn、トークン単位の増減、 シンボル単位の増減を要約する。月曜朝に LLM へ貼るだけで 前週の差分を把握できる。 

ctx digest --since 7d \
  --out monday-brief.md

FAQ

よくある質問

なぜ "Curator" なのか? — packer / packager と何が違う?

"pack" / "package" は 全部入れる前提 の梱包動作です。 ctx の主動詞は curate — 渡さないものを決める動作 — に置きます。 ctx pack --explain の出力に必ず Skipped 理由が並ぶのはこのためで、 curator が「展示しない理由」まで残すのと同じ精神です。 ctx を「repomix の代替」ではなく LLM Context Curator カテゴリの第一実装と位置づけます。

repomix とどう違うの?

repomix はリポジトリ全体を 1 つのファイルに連結する「梱包機」です。 ctx は「何を渡すか」を選り分けるための「curator + 梱包機」です。 goal-aware なスコアリング、トークン予算管理、MCP server、 監査ログ、secret 検出、replay snapshot など、 repomix にはない機能群がコア価値です。 「とりあえず全部連結」ではなく「LLM に何を渡すか選り分けたい」 というニーズに応えます。

ripgrep や ast-grep の代替?

いいえ。ctx where は「特定の文字列を最高速で grep する」 道具ではありません。自然語のゴールから LLM に渡すべきファイルを 関連度でランキングすることに特化しています。

特定の文字列を最高速で grep したい → rg。 構文木ベースのパターン検索 → ast-grep または LSP / rust-analyzer。 自然語ゴールから関連ファイル群を取り出して LLM に渡したい → ctx where + ctx pack。 それぞれ土俵が異なります。

CI で動かせるか心配

通常の CLI ビルドとテストは Rust toolchain で動作します。 GitHub Actions では dtolnay/rust-toolchain などで stable Rust を用意してください。 フロントエンドを再ビルドする場合だけ Node.js / pnpm が必要です。

air-gap 環境 (インターネット非接続) で使える?

はい。ctx はすべてローカルファーストで設計されています。 strict_offline = true または環境変数 CTX_STRICT_OFFLINE=1 を設定すると外部通信を完全に遮断します。 Google Fonts などは LP (この Web サイト) のみで使用しており、 CLI ツール本体は外部通信を一切行いません。

ライセンスは? — 現在未選定 (MIT 確定予定)

現在ライセンスは未選定ですが MIT を推奨しています。 詳細は GitHub リポジトリ を確認してください。商用利用可否はライセンス確定後に明記します。

この LP はアクセス解析を使っていますか?

現時点ではアクセス解析ツール (PostHog / GA4 等) は未配線です。 将来導入する場合は Privacy Policy ページを設け、 ここに明記します。CLI ツール本体はいかなる telemetry も送信しません。
