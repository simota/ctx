## TL;DR

The sticky-handle session API was added to the already-shipped (Phase
3, evidence-only) `ctx-replay` crate **WITHOUT touching any existing
stateless code path**. Six new query kinds (`list`, `load`, `diff`,
`diff_ids`, `selection_diff`, `prune_candidates`) ride on a single
opaque handle that caches the snapshot store plus per-id Manifest
decodings.

of two on-disk reads per request).

## Why the diff path stays evidence-only even sessioned

L1+L2+L3 screening (ADR-002):

* **L1 (caller multiplicity)**: web `/api/replay/diff` and the
  replay-pack pre-pass both call diff multiple times against the same
  store, so the base-manifest cache amortises — PASS for sessioning at
  the storage layer.
* **L2 (per-call work vs floor)**: the Compute step itself is
  445-1995 ns in Go. The cgo prologue/epilogue + JSON marshal of the
  current manifest (the diff input that cannot be cached because it's
  freshly hashed every call) is ~7-21 µs. **L2 FAIL** — even with
  zero session overhead the FFI floor dominates the workload, so a
  sessioned diff cannot beat Go for the diff math itself.
* **L3 (whose hot path is byte-scan vs map-iter)**: replay diff iterates
  two ~50-200 entry vectors and walks a BTreeMap union — map-iter, not
  byte-scan. L3 says rust gives marginal SIMD/branch benefit at best on
  this corpus size. NEUTRAL.

The base-manifest load, on the other hand, is store-IO-bound (~17-24 µs
in Go) and the session caches the decoded Manifest — a single Mutex
hash-lookup + Manifest clone. That's the win: **3× on per-call wall
clock and a flat 0.6 µs on the prune candidate scan** (vs Go's 395 µs
directory walk + decode-every-id).

The web handler ends up paying:
   1. ONE RoutedLoad (cache miss + warm) per (root, id) per process
      lifetime.
   2. ZERO additional cost on every subsequent /api/replay/diff or
      /api/replay/show against the same id.
   3. RoutedDiff with a hand-built args JSON — net wall-clock per
      additional request is ~8-23 µs vs Go's ~17-26 µs (load +
      compute) — **2-3× lower**.

So the **promotion is justified by the workload, not by the diff
microbenchmark in isolation**.

## Notes for the bench reader

The Go bench triplet sets `SetEngine("rust")` inside each `_Sessioned`
and `_Stateless` benchmark; in the default (pure-Go) build SetEngine
returns an error and the rust benches skip cleanly. The `_GoBaseline`
bench forces "go" and is the reference floor.

The rust-tagged numbers tabled above were collected with `-benchtime=1s
-cpu=10`. Soak ran at `-benchtime=5000x` to exercise the open/close
fast-path explicitly.
