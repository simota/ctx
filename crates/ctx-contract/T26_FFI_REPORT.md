Summit Phase 6 hand-off from the Rust crate to the Go CLI. This document
records the C ABI surface we expose to cgo (T-27 will consume it from

All functions are declared in `crates/ctx-contract/src/ffi.rs` and

`uintptr_t` in the header corresponds to Rust's `usize`.

### Error codes (shared by all `i32`-returning functions)

| Code | Meaning |
| ---: | --- |
| `0` | success |
| `-1` | required out-pointer (or in-pointer for non-zero len) was null |
| `-2` | input length exceeds 100 MiB (defensive cap) |
| `-3` | input bytes were not valid JSON where required |
| `-4` | internal serialisation failure (would indicate a serde bug) |
| `-99` | a Rust panic was caught by `catch_unwind`; out-params untouched |

`ctx_contract_parse_from_pack` returns `0` with `*out_found = 0` when no
contract is embedded — this is **not** an error.

## 2. Memory ownership protocol

The cgo side breaks most often here, so we spell every rule out.

### Inputs (caller -> Rust)
- All `*const u8 + usize len` and `*const c_char + usize len` buffers
  are **borrowed for the duration of the call**.
- The caller retains ownership and may free them immediately upon
  return.
- Rust never retains input pointers across calls; the crate is
  stateless (Phase 1 SPECTER finding — no globals, the few
  `once_cell::Lazy<Regex>` statics are read-only).
- `len == 0` permits a null pointer for the corresponding buffer.

### Outputs (Rust -> caller) — strings
- `*mut *mut c_char` out-params are written with pointers produced by
  `CString::into_raw`.
- The caller takes ownership and **MUST call
  `ctx_contract_free_string` exactly once** on the resulting pointer
  when it is non-null.
- It is safe to call `ctx_contract_free_string(NULL)`; it is a no-op.

### Outputs (Rust -> caller) — byte buffers
- `ctx_contract_strip_block` writes a `(ptr, len)` pair.
- The buffer is **NOT** null-terminated; `len` is authoritative.
- The caller **MUST call `ctx_contract_free_buffer(ptr, len)` exactly
  once** with the same `len` it received.
- When the stripped result is empty, Rust writes `*out_stripped_ptr =
  NULL` and `*out_len = 0`. Calling `ctx_contract_free_buffer(NULL, 0)`
  is a documented no-op.

### Outputs (Rust -> caller) — static strings
- `ctx_contract_version()` returns a pointer to a `'static` C string
  with the lifetime of the loaded library. The caller **MUST NOT free
  it**.

### Verify options JSON shape
`opts_json` is decoded into the internal `VerifyOptions`. The on-wire
schema mirrors the Rust struct verbatim:

```json
{
  "strict": false,
  "no_symbols": false,
  "worktree_root": ""
}
```

Pass `(NULL, 0)` for defaults. All three fields are optional.

## 5. Thread safety

Every public FFI function is **reentrant and safe to call concurrently
from any thread**. The Rust crate is stateless:
- No `static mut`, no `RwLock`, no globals beyond the read-only
  `once_cell::Lazy<Regex>` caches.
- `verify` reads the worktree filesystem when `worktree_root` is set;
  concurrent calls against the same worktree are safe because we only
  *read*.
- `Send + Sync` are derived implicitly for every public type the FFI
  touches.

Callers do not need to serialise access to the library.

## 6. Panic safety

Every `extern "C"` function wraps its body in
`std::panic::catch_unwind(AssertUnwindSafe(|| ...))`. On panic:
- The function returns `-99`.
- Out-parameters are written to null/zero **before** the work begins,
  so the caller never observes uninitialised memory.
- No allocation is leaked across an unwind boundary; we only call
  `CString::into_raw` / `Box::into_raw` on the success path.

## 7. Known limitations

- **Strip output is not null-terminated.** This is intentional — pack
  bodies are binary-safe — but cgo callers must avoid `C.GoString` on
  the returned pointer; use `C.GoBytes(unsafe.Pointer(buf), C.int(len))`.
- **`opts_json` is JSON, not a C struct.** This keeps the ABI stable
  when `VerifyOptions` grows new fields. Cost: one tiny JSON encode on
  the Go side per verify call.
- **Defensive size cap is 100 MiB.** Larger inputs would indicate a
  caller bug; bumping the cap is a one-line change if real-world packs
  ever approach it.
- **No streaming API.** Inputs and outputs are full buffers. Acceptable
  for packs (median <2 MiB, hard cap <100 MiB above) but worth
  remembering if Summit ever bolts on incremental verification.
- **No symbol versioning.** The C header lacks a `CTX_CONTRACT_ABI`
  constant. If the ABI ever changes, downstream cgo will need a recompile
  rather than a graceful version negotiation. Acceptable while the Go and
  Rust sides ship from the same monorepo.
